# 第四十六阶段决策：受控作业的质量与用量并排对比

日期：2026-11-13。管理员现有作业回归门槛只返回逐题通过、退化和改善。紧凑输入候选完成后，还需在同一页比较 Token、请求和字段级 Schema 指标，才能判断输入精简的实际代价与收益。

## 决策

1. 保留原有回归门槛：没有已通过题退化才算门槛通过。Token 减少不抵消正确率退化，也不自动批准候选。
2. 通过任务、fixture、判分器、身份和单变量检查后，读取两份作业的完整汇总；关联运行的完整非敏感模型配置也必须与各自作业计划一致。并排展示任务通过数、SQL 结果正确次数、Schema 宏召回/准确率、远程请求数与 Token。Token 按阶段给出差值；实际作业用量包含中断片与重试片，另显示片重试次数。
3. 只有两侧供应商 Token 用量均完整、无未知请求和重试请求时，才计算总 Token 差值、百分比和阶段差值；否则只展示已知用量及覆盖情况，差值为未知。Schema 指标只有两侧有效标注试验数相同且大于零时才给差值。请求次数仅在两侧预算计数可靠时给差值。
4. 报告不计算货币费用，不把 JSON 字符数减少率当作 Token 减少率。旧运行的阶段用量按第四十四阶段规则只读回算，不改写原始记录。

## 验收

- 同条件、单变量作业可并排比较质量和用量；若候选省 Token 但已通过题退化，门槛仍失败。
- 任一侧用量缺失、重试或未知请求时，不输出虚假的 Token 差值。
- 管理员 UI 可从两次作业的回归门槛中直接看到总量和阶段差异；无模型演示不能进入该比较。
- 后端测试、离线门禁、前端构建及 GitHub CI 通过；不发起远程候选评测。
