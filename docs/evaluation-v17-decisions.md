# 评测第十七阶段决策记录：远程请求预算

状态：已决策，2026-10-30。承接[评测路线图](evaluation-roadmap.md)与[第十六阶段决策](evaluation-v16-decisions.md)。

## 目标

给管理员主动发起的实时评测设置可验证的远程请求上限，避免任务和网络重试带来意外的无限调用。无需本地模型，不依赖供应商价格表。

## 决策

1. 实时评测每次运行默认最多发送 50 次 HTTP 模型请求；页面可选 20、50 或 100 次。后端接受 1–100 的整数且始终强制默认值，不能通过跳过 UI 获得无限预算。离线演示无请求预算。
2. Chat、Embedding 和 Rerank 的每次实际 HTTP 尝试各消耗 1 次，包括重试。计数在发送前原子递增；达到上限时下一次尝试被拒绝，绝不再调用远程接口。普通问数 API 不受评测预算影响。
3. 被拒绝的尝试抛出独立异常，不被工作流已有的“模型不可用”降级处理吞掉。评测保留当前失败试验、已有轨迹和已用次数，状态标为 `budget_exhausted`，停止后续试验。恰好用满预算且不再需要请求的运行可正常完成。
4. 运行记录、历史详情和安全摘要导出保存上限、实际已发请求数与是否耗尽。页面启动确认显示上限，报告显示预算使用情况；回归对比提示两次上限是相同、不同或旧记录未知。
5. 请求次数不是 token 或费用。供应商用量缺失时仍显示未知，不推算金额。已耗尽运行不能重放或用于已完成运行之间的回归对比。

## 验收

- 重试路径达到上限时远程发送次数不超限，普通问数不受影响。
- 评测达到上限后有明确状态与部分轨迹，不继续执行剩余题目。
- API 不能接受超出上限或不合法的预算，页面确认和报告清楚展示上限与已用量。
- 后端测试、前端类型检查及生产构建通过，并由 GitHub Actions 验证离线部分。
