# 第四十四阶段决策：评测成本与 Schema 噪声诊断

日期：2026-11-13。`stable000001` 的三题真实运行共 78,594 Token、15 次成功模型调用；字段级 Schema 宏平均召回 100%、准确率 28.68%。逐调用记录显示单数据库 Agent 准备阶段消耗 54,090 Token，Schema 检索阶段 14,638 Token。当前页面能看逐次调用，缺少作业级按阶段汇总，难以判断先优化哪里。

## 决策

1. 增加纯读取的调用成本聚合：按阶段汇总调用次数、成功/失败次数、有用量的次数、已知 Token 数。只在全部调用均有可信用量时给出完整 Token 占比；缺失用量明确显示“部分未知”，不补零或估算价格。
2. 在真实作业页面同时展示字段级宏平均召回和准确率、已知总 Token 与分阶段用量。阶段用量只使用模型调用遥测，不把 LangGraph 阶段耗时相加成总耗时。
3. 报告保留按题目可追溯的调用和字段明细；新增聚合只用于诊断，不改变 SQL、Prompt、检索、任务和判分，旧基线的实验指纹保持不变。
4. 本阶段不设货币成本：当前配置没有可信的模型单价、计价口径和缓存折扣。后续若引入价格，必须记录价格版本和计价单位。对 Schema 准确率偏低的处理，先确定噪声来自候选排序还是最终上下文，再做单变量检索实验。

## 验收

- 有完整用量时，各阶段已知 Token 之和等于运行总 Token，比例合计 100%。
- 缺失调用用量或失败调用时标记覆盖不全，不把已知 Token 说成总成本。
- 旧运行可用已有轨迹回算；无模型的演示作业不显示虚假成本。
- 本地测试、离线门禁、前端构建及 GitHub CI 通过。
