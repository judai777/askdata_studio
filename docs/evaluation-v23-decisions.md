# 评测第二十三阶段决策记录：扩展 P0 题目预审

状态：已决策，2026-10-31。承接[第二十二阶段决策](evaluation-v22-decisions.md)。

## 本轮范围与方法

对剩余开发集任务做只读技术预审：比对题面、审核说明、标准 SQL 与三套 fixture 的预期结果，并运行已登记的错误 SQL。将核验值和局限补入[首轮审核材料](evaluation-p0-review-round1.md)。本轮不提交人工审核结论，不修改现有 fixture 和 oracle。

## 发现与决策

1. 路由问候题没有 SQL 结果，受限数据库题以权限拒绝为预期；不能用普通数据题的行集核验方法替代过程与权限检查。
2. `metric.paid_vs_list`、`metric.list_amount`、`join.customer_orders`、`grain.unique_customers` 的标准 SQL 都写明 2026 年 8 月，但在 `base`、`edge_v1`、`edge_v2` 中去掉月份过滤后结果仍相同。现有 `required_time_fields` 只能证明 SQL 使用了日期字段，不能证明月份边界正确。审核材料必须明确标记该区分力缺口，不能把三套数据运行成功解释成时间口径已被充分验证。
3. 后续优先新增**版本化的第四套边界 fixture**，在当前订单中加入 8 月以外的已支付记录，并登记“漏月份过滤”的错误 SQL。旧 fixture 和指纹保持不变；新 fixture、任务审核指纹和离线门槛按版本更新。实施前先核对所有引用三套 fixture 的页面、测试和文档，再确定数据行与期望差异。
4. 题目的业务含义仍由项目管理员确认。特别核对客户按地区去重的口径、澄清题选“当前”的恢复路径，以及“销售额”是否统一指实付金额。Agent 的技术预审不得自动批准题目。
