# 评测第二十阶段决策记录：受控 A/B 候选运行

状态：已决策，2026-10-30。承接[评测路线图](evaluation-roadmap.md)、[第十八阶段决策](evaluation-v18-decisions.md)和[第十九阶段决策](evaluation-v19-decisions.md)。

## 目标

让管理员从一次已完成的实时运行创建候选运行，系统固定实验条件，仅允许选择已登记的 Chat 模型。完成后用已有回归对比查看逐题变化。每次候选运行仍由管理员明确点击确认，受既有请求预算约束。

## 决策

1. 新运行保存按提交顺序排列的 `task_ids`。只有状态 `completed`、模式 `live`、含完整 `task_ids`、请求预算和判分器指纹的基线可以创建候选。旧运行缺少这些信息时明确拒绝，不从已执行案例推断未执行任务。
2. 后端候选入口接收基线 ID 与已登记 Chat 模型名，直接复用基线的任务、fixture、试验次数和请求上限。创建前校验当前任务版本、fixture 指纹、oracle 指纹、判分器指纹与基线一致；提示词/工作流指纹和非 Chat 模型配置必须一致。远程 Chat、Embedding、Rerank 地址只保存并比较哈希，不导出原始地址。若部署或配置已变化，要求重新创建基线。
3. 候选运行记录 `baseline_run_id`。在排队和运行记录中保留实验关联；安全摘要导出包含基线 ID 与任务 ID。运行时继续使用已冻结的模型配置，不影响普通问数服务。
4. UI 在可用基线详情中显示“以此为基线运行候选”，沿用当前模型选择器。确认框写明基线模型、候选模型、任务数、试验次数、fixture、请求上限与远程费用可能性。候选完成后自动填入已有对比控件；预算耗尽、失败或取消时仍保留关联，但不参与已完成运行的直接对比。
5. 首版不自动连续触发两次远程运行，不估算费用，也不把未经人工审核的开发集分数宣称为真实能力。相同模型重复运行允许用于观察波动。

## 验收

- 非实时、未完成、旧格式或配置与实现已变的基线拒绝创建候选；非法模型拒绝。
- 候选任务、fixture、试验次数、预算和版本条件与基线一致，运行记录与导出保留关联。
- UI 能完成基线选择、候选确认、进度查看和结果对比；不会未经点击主动调用远程 API。
- 后端测试、前端类型检查与构建、离线门槛、GitHub Actions 通过，不依赖本地模型。
