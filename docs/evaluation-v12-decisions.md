# 评测第十二阶段决策记录

状态：已决策，2026-10-30。承接[评测路线图](evaluation-roadmap.md)。

## 本轮范围

建立 P0 的任务审核基础，并加入三道开发集任务：客户等级的订单数与实付销售额、地区去重客户数、历史和当前订单的跨月汇总。任务集升为 v5。三题分别覆盖 JOIN、聚合粒度和跨表时间口径；使用现有 `base`、`edge_v1`、`edge_v2`，不修改数据文件。

## 人工审核规则

1. 为全部任务维护版本化审核说明：业务意图、预期结果、过程要求和容易误判的边界。说明是审核材料，不等同于人工已核验。
2. 管理员可查看某题标准 SQL 和各 fixture 的预期结果，并提交“通过”或“退回”及文字意见。系统记录审核人、时间和任务指纹；初始状态全部为“待审核”，不得由代码或 Agent 自动批准。
3. 指纹由单题定义、单题 oracle、审核说明和三套 fixture 指纹生成。任一组成部分变化，历史审核标为“已过期”，需要重新审核；新增其他题不使当前题的审核失效。
4. 审核记录保存在本地 `backend/data/eval_reviews.json`，不进入版本化题库。评测运行保存所选题在启动时的审核状态汇总；未审核题仍可用于开发调试，但报告明确显示审核覆盖度。
5. 标准 SQL 仅通过管理员预览接口返回；普通任务目录继续不暴露答案。审核状态与判分结果分开，人工批准不改变自动判分。

## 本轮边界

这 14 道题仍属于开发集，不宣称为独立保留集。后续先增加足够多的人工审核题，再按版本建立保留集及私有答案。当前批准操作由项目管理员承担，演示账号的身份记录只证明谁点击了按钮，不能代替外部专家复核。

错误 SQL 清单提升为 v1.3，分别为新三题加入错误 JOIN、漏去重和错用当前表的反例。14 条固定样例在 `base`、`edge_v1`、`edge_v2` 上分别识别 10、13、14 条；这只验证所列反例，不代表完整错误覆盖。

## 验收

- 新三题 oracle 在三套 fixture 上可执行，离线评测和重放通过。
- 每题有审核说明；预览与提交接口仅管理员可用，审核意见和指纹持久化。
- 题目或答案变化后原审核显示过期；运行报告保留审核覆盖度。
- 后端测试、前端类型检查和生产构建通过。
