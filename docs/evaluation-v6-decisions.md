# 评测第六阶段决策记录

状态：已决策，2026-10-30。承接 [第五阶段决策](evaluation-v5-decisions.md)。

## 问题与选择

现有任务 JSON 同时含公开问题和标准 SQL，管理员目录接口会返回标准答案。所有题只在一份固定 CSV 上执行，某些错误过滤条件可能恰好得到相同结果。

本阶段将标准 SQL 移至 `backend/evals/oracles.json`，任务目录不含 SQL。增加 `edge_v1` fixture：在临时目录复制原始 `askdata_mock` CSV，再按版本化清单插入已支付、取消、退款、折扣及日期边界记录。原始 CSV 不被修改。

## 运行规则

1. 每次运行选择 `base` 或 `edge_v1`。Agent 的 DuckDB 工具和 oracle 必须指向同一个 fixture 根目录；权限探针也使用该根目录。
2. 运行记录保存 fixture ID 和包含基础 CSV、变异清单内容的指纹。只比较相同任务版本、模式、试验次数及指纹的运行。
3. 临时 fixture 仅在当前运行期间存在；重放时按相同变异清单重建。任务集版本提升为 4.0，旧记录仍能浏览和相互对比，不能用新答案重放。
4. UI 展示 fixture 选择与边界数据说明。离线演示依旧只验证评测管线，不代表模型能力。
5. Oracle 文件不经目录 API 返回；它仍在本地仓库，不作为保密考试答案。正式招聘评测需要另行设计私有 test split。

## 验收

- base 和 edge_v1 的 11 题 oracle 都能运行。
- 边界行能揭露至少两种错误 SQL：漏掉已支付状态、错误日期端点或错误金额字段。
- 实时 Agent 与 oracle 使用同一 fixture；重放能复现边界数据并核对指纹。
- 后端测试、前端类型检查及生产构建通过。
