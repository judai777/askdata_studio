# 第四十三阶段决策：真实轨迹审核与受控 Prompt 对比

日期：2026-11-13。`stable000001` 的三道题中，`mock.target_comparison` 和 `grain.unique_customers` 的实际 SQL 均没有订单 8 月日期条件，`time.july_august` 正确使用两个月份过滤。三题均执行了数据库 SQL；前两题结果与标准行集不符。该核对是技术预审，不代替项目使用者批准测量基线，也不写入人工标签。

## 决策

1. 提供固定、代码内登记的评测 Prompt 版本：`default` 与 `time_filter_v1`。后者只在单数据库 Agent 系统提示末尾增加“逐项检查题面时间范围、为每个事实表分别加过滤”的通用指令；不包含标准 SQL、题目 ID 或答案。普通问数默认保持 `default`。版本选择随作业计划、运行记录和导出摘要保存，且记录非敏感指纹，不保存完整 Prompt。
2. 作业创建时冻结 Prompt 版本和源码指纹。续跑必须能重新解析出完全相同的计划；版本内容变化须换作业 ID。真实作业仍需已审核任务、显式远程授权和总请求上限。
3. 回归门槛只接受单一变量：Chat 模型变化，或 Prompt 版本/Prompt 源码指纹变化；不可同时变化。题目、fixture、试验次数、判分器、字段标签、评测身份、请求预算、工作流源码以及 Embedding/Rerank 等配置必须一致。旧基线没有 `prompt_variant` 时按 `default` 解读，不重写旧运行。基线仍需人工批准。
4. 对比报告明确变量类型、逐题改善和退化。通过门槛要求没有已通过题退化；报告继续显示候选总分，避免只看“不退化”而误认为质量达标。
5. 首轮只做单数据库 Agent 的 Prompt 变体，不同时调整检索参数或业务数据。三题样本只用于验证功能与定位失败，后续扩大人工审核集再判断效果。

## 验收

- 默认问数不附加实验指令；`time_filter_v1` 只在评测中生效。
- UI 可选择版本并在付费确认中显示版本和请求上限；作业详情可看到版本。
- 单一 Prompt 差异可以过比较前置条件；同时换模型、换工作流、换数据或判分器被拒绝。
- 离线测试、前端构建和 GitHub CI 通过；新实时候选由用户在审核基线后发起。
