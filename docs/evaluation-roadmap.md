# Agent 评测后续路线图

状态：P2 阶段完成；P0 执行中，P4 报告导出、离线 CI 门槛与远程请求预算已实现，2026-10-30。承接[评测结构与流程](evaluation-architecture.md)、[第十四阶段决策](evaluation-v14-decisions.md)、[第十五阶段决策](evaluation-v15-decisions.md)、[第十六阶段决策](evaluation-v16-decisions.md)和[第十七阶段决策](evaluation-v17-decisions.md)。每一阶段先记录具体决策与验收规则，再修改代码。

## 当前基础

已有 14 道开发集任务、三套固定 fixture、14 条错误 SQL 审计样例、确定性判分、离线演示、远程实时评测、Pass³、权限探针、后台进度与取消、历史重放、回归对比、调用用量、实现来源指纹、阶段级观测与失败归因、摘要导出及管理员人工审核入口。新增审核说明不等于已获人工通过；现有任务与错误样例尚不能作为真实模型能力的充分证据。

## P0 · 任务集可信度

从真实业务问法扩展人工核验的任务，优先覆盖复杂 JOIN、聚合粒度、时间口径、歧义澄清、连续追问、越权与错误恢复。每题定义输入、数据库状态、可接受结果、过程要求、反例和人工审核记录。建立开发集与独立保留集；保留集不在管理员目录或常规调参过程中暴露标准答案。每次增加 fixture 时保持旧版本与指纹不变。

验收：先形成一个小而可信的人工核验集；每个任务能解释判分依据，关键错误 SQL 能在对应 fixture 上被识别。任务数量是覆盖面的辅助指标，不替代人工质量检查。

## P1 · 判分器校准与人工复核

为结果、SQL 安全、澄清流程和报告质量分别准备人工标注的正反轨迹，统计判分器误判和漏判。确定性规则继续负责可精确验证的维度；自然语言说明与报告质量可增加可选的远程 Judge，但须先用人工标注校准，并保留分项理由、费用与人工复核入口。对判分器本身做版本记录。

验收：每种判分维度有可复现的正反样例；修改判分器时能看到与人工标签的一致性变化。远程 Judge 的分数不得未经校准直接代替确定性结果。

## P2 · 失败归因与阶段观测

阶段已完成：实时评测记录 LangGraph 节点、MCP 工具和模型调用所属阶段；页面显示试验轨迹、逐题与运行聚合、共同题阶段差值。失败试验区分阶段异常、判分未通过和评测执行异常，逐题显示主要排查位置，整次运行按失败试验聚合。离线演示和旧运行缺少阶段数据时不伪造数据；父子阶段耗时重叠，不能相加当作总耗时。详见[第十三阶段决策](evaluation-v13-decisions.md)与[第十五阶段决策](evaluation-v15-decisions.md)。

在预处理、Schema 检索、数据库 Agent、工具执行、结果整理等阶段记录耗时、是否成功、失败类型和安全的摘要；把阶段指标汇入逐题轨迹。页面按失败阶段聚合，帮助区分模型、检索、SQL 执行和服务错误。继续不保存密钥、原始 Prompt 或敏感响应正文。

验收：一次失败能定位主要失败阶段；同一任务的两次运行可比较阶段耗时与调用量，并明确缺失的供应商用量。

## P3 · 可控 A/B 实验

在管理员页面选择已登记的远程模型配置或 Prompt 版本，冻结为运行快照。对相同任务、fixture、试验次数和判分器版本运行基线与候选；展示逐题退化、改善、稳定性与成本。保留现有确认和样例数量限制，不要求下载本地模型。

验收：两次实验的变量和不变量可审计；配置差异能在报告中解释，旧记录缺失来源信息时不推断相同。

## P4 · 自动化与交付

JSON 摘要导出已完成，保留运行版本、来源、判分、调用和阶段指标；原始问题、SQL、数据行、模型正文与异常正文不进入下载文件。[第十四阶段决策](evaluation-v14-decisions.md)。离线 CI 门槛已接入后端测试、固定数据生成、版本/指纹核对与错误 SQL 区分力审计，前端也运行类型检查和构建。[第十六阶段决策](evaluation-v16-decisions.md)。实时评测已增加每次运行的远程 HTTP 请求上限，包含 Chat、Embedding、Rerank 和重试；耗尽时保存部分报告并停止后续试验。[第十七阶段决策](evaluation-v17-decisions.md)。

增加可导出的评测报告和轻量回归门槛：离线规则与 fixture 审计进入 CI；远程模型评测由人工触发或受预算限制的计划任务执行。再评估断点恢复与持久作业队列；当前单进程后台执行器和取消机制足够支撑本地演示。

验收：一次改动能生成可分享的任务版本、数据指纹、判分依据、逐题差异与成本摘要；CI 不把离线演示分数当模型准确率。

## 推荐下一步

P0 第一批三题与审核记录功能已实现。下一步请项目管理员逐题核对审核说明、标准 SQL 和三套 fixture 结果，留下实际审核意见；随后补更多真实业务任务，再建立独立保留集。完成这些工作后，P1 的判分器校准才有可信标签，P3 的模型比较才有可靠评测基础。
