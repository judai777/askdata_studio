# 评测第十六阶段决策记录：离线回归门槛

状态：已实现并本机验证，2026-10-30。承接[评测路线图](evaluation-roadmap.md)。

## 目标

让不具备本地模型和远程 API 密钥的开发环境也能复现评测基础检查，并在任务、标准答案、fixture 或错误 SQL 样例意外变化时得到明确失败报告。

## 决策

1. 增加一个只读离线门槛命令。它读取当前任务清单与错误 SQL 审计，核对版本和指纹、样例数量、各 fixture 的无效 SQL 数量，以及 `edge_v2` 对全部已登记错误样例的识别情况。失败时列出具体差异并以非零状态退出。
2. 将当前已经验证的任务版本与任务文件内容、oracle、mutant 和三套 fixture 指纹保存为仓库内的门槛基线。正常扩题或修改数据时，开发者需检查审计结果，再显式更新基线；门槛不自动改写基线。
3. GitHub Actions 在 Python 3.11 环境安装后端依赖，以固定种子生成问数示例与电商合成数据及 Schema，运行后端测试和离线门槛；在 Node 22 环境运行前端 `npm ci` 与生产构建。CI 不设置模型密钥，不调用远程评测。
4. 本地可使用同一门槛命令。数据未生成时明确报错并提示先运行示例数据生成脚本；门槛本身不改写已有 CSV、运行记录和人工审核。
5. 离线演示通过率只用于体验流程，不作为模型准确率或 CI 质量阈值。门槛的识别率只代表已登记的 14 条错误 SQL。

## 验收

- 当前仓库的离线门槛通过；指纹变化、无效 SQL 和漏检样例均导致失败并显示原因。
- 后端全量测试、前端类型检查与构建通过；CI 工作流有可本地复现的命令。
- 无需下载本地模型，也无需配置远程 API 密钥。
