# 评测第十五阶段决策记录：完成 P2 失败归因

状态：已实现，2026-10-30。承接[评测路线图](evaluation-roadmap.md)与[第十三阶段决策](evaluation-v13-decisions.md)。

## 决策

1. 每次失败试验生成一个主要归因：`stage`（工作流阶段失败）、`grader`（运行阶段无明确失败，但确定性判分未通过）或 `runner`（评测执行异常且没有阶段记录）。通过的试验归因为 `null`。
2. 一次试验有多个失败阶段时，优先选择失败的 MCP 工具子阶段；否则选择最早出现的失败阶段。这个规则给出排查起点，不宣称自动推断唯一根因。
3. `grader` 归因只列出失败的检查项，不把结果不符直接推断为检索或模型错误。异常正文、SQL、模型正文不进入归因字段。
4. 逐题展示首个失败试验及其归因；整次运行按失败试验聚合数量。重放时根据重新判分的结果重算归因。旧记录不补造归因；离线演示通过时无失败归因。
5. 回归对比在双方都有新归因字段时显示归因变化；安全 JSON 导出只保留归因类型、固定阶段名、检查项与试验序号。

## 验收

- 工具错误、普通阶段错误、判分未通过与无阶段的执行异常能区分；通过试验不显示失败归因。
- 页面能直接看到逐题主要失败位置及运行聚合，不用逐条翻阅原始 JSON。
- 旧运行与离线演示不出现编造的阶段错误，导出不泄漏异常正文。
- 后端全量测试、前端类型检查与生产构建通过。
