# 第四十六阶段验收：受控作业的质量与用量报告

日期：2026-11-13。决策见[第四十六阶段](evaluation-v46-decisions.md)。管理员在“检查逐题回归门槛”后，现在同时看到任务通过、退化/改善、SQL 结果正确、字段级 Schema 宏指标、远程请求、完整或已知 Token，以及分阶段 Token 差值。

## 比较口径

- 回归门槛仍以“没有已通过题退化”为准；成本下降不改变门槛结论。
- 用量统计包含一个作业的所有实际运行片；若有片重试，报告显示次数且不提供直接 Token 差值。任一侧缺少供应商用量、有重试请求或中断请求时，只展示已知 Token，不计算节省比例。
- Schema 差值仅在两侧有效标注试验数相同且大于零时计算。SQL 结果正确次数只在两侧有效试验数相同时比较。没有可信单价，因此不报告货币成本。

## 验证

- 本地 142 项后端测试通过，离线 SQL 门禁通过，前端类型检查与构建通过。测试覆盖候选 Token 较少但已通过题退化时仍判门槛失败，缺失用量、片重试时不产生虚假 Token 差值，以及关联运行的 Embedding 配置漂移被拒绝。
- 在临时目录中复制 `stable000001` 及其运行记录，临时批准副本并构造同内容的紧凑版候选记录；门槛识别为 Prompt 单变量，展示 1/3 → 1/3、15 → 15 次请求、Token 差值 0 和 Schema 宏召回 100% → 100%。此步骤只验证旧记录兼容和报告计算，**没有真实运行紧凑版模型，也没有批准原始基线**。

下一步仍需项目使用者核对[三题人工审核卡](evaluation-v43-review.md)并决定是否批准 `stable000001` 为测量基线；获批后才运行 `compact_context_v1` 或 `time_filter_v1` 的真实候选，观察质量和 Token 的实际变化。
