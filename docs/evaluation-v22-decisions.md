## 核验与修订决策

1. `join.customer_orders` 的订单数按 `COUNT(DISTINCT order_id)`，销售额按已支付订单的 `paid_amount` 汇总，按 `customer_id` 关联客户等级。保留现有答案和题面。
2. `grain.unique_customers` 按地区对已支付、2026 年 8 月订单的 `customer_id` 去重。保留现有答案和题面；新增订单不会必然改变去重客户数。
3. `time.july_august` 的 7 月取历史表、8 月取当前表，各自过滤月份和已支付状态，输出两行。保留现有答案和题面。
4. `mock.target_comparison` 的题面没有指定目标月份，但标准 SQL 固定选择 2026 年 8 月，数据中同时存在 7 月和 8 月目标。把题面明确为“对比2026年8月各地区已支付订单的实付销售额和当月销售目标”，与既有答案及审核说明一致。此变更会使该题审核指纹失效，因此任务版本从 5.0 升为 5.1，并审查后更新离线门槛的任务指纹。
5. 保留原有 fixture、oracle 和错误 SQL 样例。用三套预期结果、错误 SQL 审计、后端测试及离线门槛验证修订。
