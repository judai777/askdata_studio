# 第四十五阶段决策：单库 Agent 的紧凑 Schema 输入实验

日期：2026-11-13。第四十四阶段发现 `stable000001` 的单库 Agent 准备阶段占 54,090/78,594 Token。对三题原始轨迹的输入结构做静态检查：每题检索命中 `retrieval.hits` 的 JSON 约 24–26 千字符，Schema 图约 6.9–8.1 千字符，Schema 文本约 1.5–1.8 千字符。命中项带检索排名、向量文本、样例和来源元数据；其中字段名、描述、表名等已在 Schema 图中再次提供。

## 决策

1. 新增评测专用 Prompt 版本 `compact_context_v1`。默认版本和 `time_filter_v1` 保持原输入。紧凑版本在单库 Agent 的模型输入中，保留完整 Schema 图、Schema 文本、低置信度候选、确认参数、工具定义和用户问题；仅把 `retrieval.selected_fields` 的完整命中对象替换成所选字段 ID 列表。列表必须按原检索顺序、数量和 ID 保留，不改检索器输出、Schema 图或数据库执行路径。
2. 系统指令说明字段详情应从 `schema_graph.fields` 读取，所选字段 ID 仅表示检索排序。此实验不添加标准 SQL、目标字段标签或答案，不能从评测题目 ID 特判。
3. 版本与源码指纹写入作业和运行来源；只允许在已批准基线下作为 Prompt 输入单变量比较。管理员仍需确认远程请求上限。先做离线 payload 大小核对和功能测试；真实模型是否省 Token、是否影响正确率必须等候选作业完成后才能判断。
4. 本轮不同时削减字段数量、压缩 Schema 图或改变 Rerank 参数。若紧凑版损害结果，保留默认版，不以字符数代替效果结论。

## 验收

- 默认版输出 payload 与现状一致；紧凑版保留字段 ID 顺序、Schema 图、Schema 文本及工具定义。
- 基于三题旧轨迹重建同等输入时，紧凑版 JSON 字符数下降；只报告字符数，不推算供应商 Token 节省。
- 旧基线工作流指纹不变；本地测试、离线门禁、前端构建和 GitHub CI 通过。
