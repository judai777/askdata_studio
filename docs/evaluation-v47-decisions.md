# 第四十七阶段决策：额外派生列与旧运行重判

日期：2026-11-13。项目使用者在逐题审核中确认：`mock.target_comparison` 若地区、实付额、目标正确，可接受额外的“差额”和“完成率”派生列；并确认三道真实轨迹的人工标签。三条标签已写入本地运行 `f60a2e161439`：前两题完成失败、回答质量失败、安全与过程通过，第三题四项通过。原始运行和人工标签仍在本地，不随 Git 推送。

## 发现

原始目标对比 SQL 漏掉 `orders_current.order_date` 的 8 月过滤，华东实付额 4,294,106.75，标准为 4,293,983.75，差 123。只补日期条件后，前三列与标准完全一致，但模型还输出“差额”“完成率百分比”，现有 `_rows_equal` 要求严格列数相同，仍会判结果失败。这说明时间错误与附加列口径是两个独立原因。`grain.unique_customers` 的华东实际 9 人、标准 8 人；`time.july_august` 两月结果正确。

## 决策

1. 只对目标对比题接受追加的派生列。必需的地区、实付额、目标仍须按前三列与标准答案逐行一致；允许的附加列限定为“差额”“完成率百分比”，且数值必须分别等于实付额减目标、实付额除以目标乘 100 后保留两位。其他题继续使用现有严格列数规则。额外未知列或错误派生值不得通过。此规则属于确定性判分器，必须进入判分器指纹。
2. 原始运行的 SQL、结果、原始判分指纹和人工标签不改写。新判分器可重放旧输出生成新判分结果；旧运行的 `grader_hash` 仍是原值，不能静默与新版本候选比较。
3. 为避免仅因判分规则变化而再次支付相同模型调用费用，允许从**已完成、无片重试**的真实作业生成一个本地重判副本：逐试验按当前任务、oracle、fixture 和判分器重算；新作业与运行记录保存源 ID、旧判分器指纹和新指纹，保留原始模型输出、实验来源和历史调用用量，并明确“没有新增远程调用”。副本须再次人工审核并批准后才能作为新基线。只有通过当前任务/数据/来源验证的旧记录可转换。
4. 对比门槛仍要求新基线与候选的当前判分器、任务、fixture、工作流、身份和非变量配置一致。重判副本不自动继承旧基线批准状态；人工标签仍附着原始轨迹，不自动复制为新运行标签。

## 验收

- 目标题日期正确且派生列正确时通过；漏日期、错误差额、未知额外列和其他题额外列均失败。
- 重判副本不调用远程模型、不覆盖源记录，能显示源作业/运行与两版判分器指纹；失败或部分运行不能转换。
- 原始运行仍可查看旧判分与用户确认的三条有效人工标签；新副本需人工批准后才可用于受控 Prompt 候选。
