# 评测第二阶段决策记录

状态：已决策，2026-10-30。承接 [首版决策](evaluation-decisions.md)。

## 讨论与取舍

用户希望继续扩充题库并加入稳定性。检查首版后确认：四道题只覆盖聚合、JOIN、路由；所有实时题以管理员身份运行，无法测普通用户越权；任务结果只保存一次输出，不能计算稳定性。

本阶段决定：

1. 新增固定日期的时间过滤题、澄清并恢复题、受限账号越权探针。每种任务明确 `kind`，避免把工具护栏测试冒充模型能力。
2. 澄清题记录首次暂停结果与恢复结果；判分同时检查选项和恢复后的结果。实时执行时按任务指定选项调用 `clarify`。
3. 安全探针直接调用 DuckDB 执行器，以 `demo_current_sales` 身份尝试访问 `askdata_mock`，通过条件是明确拒绝。它属于系统护栏分数，不计入模型任务的 Pass³。
4. 模型任务支持 1 或 3 次独立试验，每次创建新 session。Pass³ 仅在三个 trial 都通过时成立；同时展示每题三次结果。离线演示允许试验三次，但标注为流程演示，不代表模型稳定性。
5. 保留每次运行最多 5 道题；三次试验时最多 3 道实时题，以约束费用与请求时长。UI 明确显示预计调用次数。
6. 任务集版本提升到 2.0，数据集指纹继续记录。历史 v1 记录可查看，但由于任务版本变化不能重新判分。

## 验收

- 离线模式能体验新增的时间、澄清、安全任务；每题展示对应轨迹或防线输出。
- 实时模式可选 1/3 次，显示 trial 明细、通过率和 Pass³；受限题不调用模型。
- 时间 oracle、澄清恢复与越权拒绝都有后端测试；所有旧测试继续通过，前端生产构建通过。

## 后续

下一阶段应增加人工核验的业务口径变异数据，以及后台作业和逐题进度。真正的模型稳定性数字需要用户主动运行远程 API 后才能报告。
