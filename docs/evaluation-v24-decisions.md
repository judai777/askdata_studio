# 评测第二十四阶段决策记录：建立可验证的 430 题基准

状态：方向已由项目使用者确认，2026-10-31；尚未开发或宣称达到旧指标。承接[评测路线图](evaluation-roadmap.md)。

## 用户决策与目标

先以旧 V2 材料中的 **430 题**为目标规模；原始题目、标准 SQL 和 `short_video_ops` 数据不可得，改用当前项目的数据重新构建评测集。目标是让当前项目能独立、可复现地测量 Schema 字段召回率/准确率、SQL 执行成功率、结果正确率和耗时。旧材料的 95.26%、19.44%、99.30%、82.56% 只能作为参考目标，不能称为“复现”或预设实验结果。

## 数据与人工审核

1. 以当前 `ecommerce_ops` 的固定合成数据为首个基准数据域。保存数据生成脚本版本、数据指纹、表/字段/行数，不把旧短视频业务场景的规模当成当前数据事实。
2. 每题记录问题、业务意图、复杂度、标准 SQL、目标字段集合、排序要求、可接受误差和过程约束。目标字段以标准 SQL 和人工审核共同确定；别名、隐含关联键、聚合字段如何计入必须写成统一规则。
3. 先设计并人工审核 49 道开发集题（32 简单、15 中等、2 复杂），覆盖多表 JOIN、聚合粒度、时间边界、金额口径、比率、CTE、权限与澄清。随后增补 381 道保留题，使总量达到 283/132/15。不得通过同一 SQL 的口语改写批量凑数；同义改写应标记题族，并按题族拆分开发集与保留集。
4. 标准答案和保留集不进入模型可见的 Schema 文本、Prompt 或日常调参报告。每次变更题目、答案、数据或判分规则都生成版本指纹，旧结果不得混算。

## 指标定义

| 指标 | 新基准的计算方式 |
| --- | --- |
| 字段级 Schema 召回率 | 对每题计算 `|目标字段 ∩ 最终召回字段| / |目标字段|`，再对有效题取宏平均；同时报告覆盖数和按复杂度分层结果 |
| 字段级 Schema 准确率 | 对每题计算 `|目标字段 ∩ 最终召回字段| / |最终召回字段|`，再取宏平均；空集合、用户强制加入字段和权限剔除按版本化规则处理 |
| SQL 执行成功率 | 真实模型生成的 SQL 经只读与权限校验后成功执行的题数 / 有效题数；澄清、拒绝和无 SQL 的任务另列，不混入此分母 |
| 查询结果正确率 | 真实 SQL 执行结果与人工核验 oracle 在相同数据快照上按版本化规则比较，正确题数 / 有效题数；排序、数值误差、NULL、重复行和列语义单独定义 |
| 耗时 | 分别报告模型端到端、SQL 工具执行的均值与 P95，注明样本、超时和失败是否进入分母；不把二者混称“SQL 耗时” |

## 实施顺序和验收门槛

1. **评测格式与判分协议**：确定字段标注格式、行集等价规则、分母和异常处理；先用人工构造的正反例验证判分器，记录决策后实现。
2. **49 题开发集**：逐题审核与错误 SQL 审计，通过后做小批量真实运行，保留失败轨迹；没有 API Key 时只完成离线题目与判分验证，不填模型指标。
3. **批量执行器**：在现有单次 5 题限制之外增加有预算上限、断点恢复、失败重试记录和来源快照的批处理；先验证重启后续跑及重复提交不会重复计数。
4. **381 题保留集**：由人工审核题目与答案，冻结后一次性运行；按复杂度、题族和失败类型出报告，并对抽样轨迹做人工复核。
5. **结果发布**：同时给出分子/分母、百分比、数据版本、模型版本、Prompt/工作流/判分器指纹、运行日期与费用/用量覆盖。任何“达到旧指标”的说法必须基于新基准的实际结果，并明确它与旧数据集不可直接比较。

## 当前阻塞项

当前环境没有远程 API Key，不能测真实模型指标；430 题与人工标准答案尚不存在。旧 V1 的研究所部署、50 用户、600 题单库/多库和回溯提升数字属于另一组实验，本阶段不纳入验证，也不由新基准推导。
