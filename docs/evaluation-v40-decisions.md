# 评测第四十阶段决策：可恢复的自动化评测作业

日期：2026-11-10。承接[430 题基准定义](evaluation-v24-decisions.md)与[评测路线图](evaluation-roadmap.md)。现有单次运行最多 5 题，有后台进度和取消；CI 自动运行确定性测试与错误 SQL 门槛，但没有跨多次运行的作业记录与续跑。

实施前已核对 OpenJudge、Claw-Eval、Langfuse 与 LangSmith 的公开架构，来源、取舍和本项目模块映射见[评测平台结构调研](evaluation-platform-research.md)。核心结论是让作业层编排现有单次运行，把数据版本、逐题轨迹、判分和人工反馈保留在各自模块。

## 决策

1. 增加命令行评测作业。输入固定题目 ID、fixture、试验次数和模式；按现有单次运行上限分片执行，作业清单和每片运行记录原子落盘。同一作业 ID 再次启动时，核对题目、数据、标准答案、判分器和字段标签指纹，只执行未完成片。中断片保留历史运行 ID，重试生成新运行 ID；汇总每片仅计一次。实时中断片的重新运行需要再次显式同意，因为远程请求可能重复并产生费用。
2. 无模型演示模式用于验证作业编排和 CI，不作为 Agent 正确率。实时模式必须显式传入允许远程调用的开关与总 HTTP 请求预算；总预算包含各片实际用量，耗尽后停止。没有已配置密钥时不启动实时作业。
3. 第一版只允许一个数据库和一个 fixture，每片沿用现有运行器的任务上限。已有单题运行、管理员评测页和人工审核流程继续使用原接口。作业记录保存在被 Git 忽略的本地运行目录，导出的作业摘要只包含任务 ID、运行 ID、版本指纹和计数，不包含 SQL、结果行或模型正文。
4. CI 增加一个版本化的六题清单和无模型作业冒烟步骤，验证分片、持久化与完整汇总。实时评测不在 push 时自动消费远程 API；未来可用受预算限制的工作流调度，并需独立保存费用和失败通知。
5. 管理员评测页只读展示本地作业清单、进度、片状态与关联运行 ID；复用已有运行详情查看证据。API 只返回安全摘要，不暴露作业计划中的模型配置、SQL 或结果行。作业启动和远程调用仍通过显式命令行参数执行。

## 验收

- 超过 5 题会自动分片；重复启动相同作业不会重复执行已完成片。
- 模拟中断后继续时，只补运行中断片；作业参数或数据指纹变化时拒绝复用旧作业 ID。
- 汇总只统计最终完成的各片，清楚标识部分完成、预算耗尽和失败；无模型与实时运行严格区分。
- 本地回归、离线门槛、前端构建与 GitHub Actions 通过。
