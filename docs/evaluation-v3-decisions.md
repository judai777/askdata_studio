# 评测第三阶段决策记录

状态：已决策，2026-10-30。承接 [第二阶段决策](evaluation-v2-decisions.md)。

## 背景与方案

用户继续推进业务口径题库与后台进度。当前同步 `/api/eval/runs` 必须等待整组任务结束，UI 只有“运行中”状态；浏览器超时会丢失页面结果。现有任务的固定 CSV 同时包含 `order_amount`、`paid_amount`、已支付/退款/取消状态及明确的 `order_date`，适合做业务口径与时间边界题。

本阶段决策：

1. 增加实付销售额、原价金额、单日边界和历史月份题；在任务中标记必需的金额/时间字段，除结果等价外再做字段检查。任务集升为 v3，历史记录仍可浏览，跨版本重放仍拒绝。
2. 新增 `POST /api/eval/runs/start` 返回运行 ID；后台单线程顺序执行，服务端每次试验结束持久化进度。`GET /api/eval/runs/{id}` 可查询运行状态、已完成试验数和部分结果。旧同步接口保留用于脚本与测试。
3. 同时最多一个后台运行。运行记录使用原子替换写入；服务重启后旧的 `running` 记录被标成 `interrupted`。首版不提供强制取消，因为无法安全中断正在等待的模型 HTTP 请求。
4. UI 启动后轮询状态并展示 `completed_attempts / total_attempts`、当前题目和局部结果。切换页面后可从历史记录重新打开运行。运行结束、失败或中断即停止轮询。
5. 不引入队列服务或独立 worker。此实现限定为本机单 FastAPI 进程；多 worker/多实例部署前必须替换为共享作业队列和外部状态存储。

## 验收

- 新题的 oracle SQL 在固定数据集执行成功；错误金额字段或时间字段不能通过。
- 后台启动立即返回 ID，能查询逐题进度及最终报告；并发启动返回明确冲突。
- 后端测试、全量回归和前端生产构建通过。

## 后续

继续扩充人工核验题库与变异 fixture；为长任务加入真正可取消的外部 worker、模型耗时和 Token 统计；评估模型配置之间的回归差异。
