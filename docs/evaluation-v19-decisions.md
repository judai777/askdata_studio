# 评测第十九阶段决策记录：判分器版本与可比性

状态：已决策，2026-10-30。承接[路线图](evaluation-roadmap.md)的 P3 阶段及[第十八阶段决策](evaluation-v18-decisions.md)。

## 问题

回归对比已经校验任务版本、fixture、标准答案、模式和试验次数，却未记录判分规则版本。若规则或 SQL 解析器改变，分数差异可能来自判分器，而非模型。

## 决策

1. 对 `_normalize`、`_rows_equal`、`grade`、`combine_attempts` 的源码片段及 SQLGlot 版本做确定性短哈希，作为 `grader_hash`。任务、fixture、oracle 已有独立版本与指纹，不重复纳入。判分器哈希针对当前确定性规则，不表示人工校准质量。
2. 新运行排队和执行记录都保存 `grader_hash`，摘要导出也包含它。判分规则仅在部署代码改变时变化；后台单进程运行期间不会热替换代码。
3. 两次已完成运行的判分器哈希均存在且不同时，拒绝直接比较并给出明确原因。任一旧运行缺失时允许查看逐题对比，但标记 `unknown`，不推断一致。
4. 历史重放保留原始 `grader_hash`，另返回 `replay_grader_hash`；如果不同，页面提示本次重判采用新规则。重放结果仍不覆盖历史原始记录。
5. UI 在运行报告和对比结果中展示哈希或未知状态；不显示源码、模型请求内容或密钥。

## 验收

- 同代码与 SQLGlot 版本得到相同哈希；规则或解析器版本变化得到不同哈希。
- 新运行、导出和重放能正确携带判分器版本。
- 已知不同版本拒绝比较；旧记录缺失版本时给出明确提示。
- 后端测试、前端类型检查/构建与离线门槛通过，GitHub Actions 通过。
