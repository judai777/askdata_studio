# 评测系统首版决策记录

状态：已决策（2026-10-30）。本文件记录讨论结论、依据和后续验证方式；代码实现以此为范围。

## 背景与目标

AskData Studio 已有路由、Schema 检索、单库 Agent、MCP、SQL 校验、DuckDB 执行及结果说明。现有 `backend/tests` 主要使用模拟模型验证代码行为，缺少对真实任务的批量评测、结果判分、轨迹保存与回归分析。本机内存不足以运行本地大模型。

首版目标是让用户在本机体验“选任务 → 运行 → 查看轨迹 → 分项判分 → 查看汇总 → 重放历史运行”的完整流程，并能选择性调用已配置的远程模型。后续交付项目结构图与评测流程图。

## 决策与依据

1. **UI**：在现有 Vue 应用增加管理员评测页。沿用已有登录和 API，避免维护第二套前端。普通用户不能访问评测 API。
2. **任务集**：使用版本化 JSON 任务定义。首批 4 题覆盖单表聚合、多表关联和路由；澄清与权限攻击题留待下一批人工标注。每题包含输入、预期路由、oracle SQL、必需表和分类标签。任务与测试数据版本绑定。
3. **运行模式**：离线演示/回放模式无需模型和 API Key；实时模式由管理员在 UI 主动启动，首版限制任务数和并发，显示会调用远程 Chat、Embedding、Rerank。不能把离线样例的分数当作真实模型能力。
4. **判分**：借鉴 OpenJudge 的分项 grader 和汇总思路。首版确定性验证路由、结果等价、SQL 必需表、只读 SQL 结构和工具调用预算；权限攻击与检索字段 recall 的独立 grader 留待后续。自然语言质量的 LLM grader 暂不进入总分。SQL 字符串不作为正确性标准。
5. **任务与轨迹**：借鉴 Claw-Eval 的 task、fixture、trace 和 completion/safety/process 分维度结构。首版保存每次运行的输入、配置摘要、输出、判分和错误，支持历史重放；多次 trial 的 Pass³ 留作下一阶段，避免单次演示误报稳定性。
6. **隔离与成本**：每个 case 使用独立 session，数据集只读。实时运行顺序执行且有数量上限；失败要有明确状态，不允许以模型失败后的兜底回答计为成功。API Key 不落入轨迹。
7. **边界**：沿用已有 DuckDB、LangGraph 和 Vue，不引入 OpenJudge/Claw-Eval 整套依赖或容器平台。现有 `tests` 继续负责工程回归，`evals` 负责模型/Agent 行为评测。

## 首版验收

- 管理员能查看任务分类、问题、历史运行和汇总。
- 无 API Key 时能完成一次离线全流程，查看每题轨迹与失败原因，并重放已存结果重新判分。
- 有 API Key 时可手动选择少量任务实时运行，看到运行中状态、完成率、安全结果和分项分数。逐题进度属于后续后台作业阶段。
- 结果等价判分处理行顺序、四位小数标准化、NULL；安全违规不能被平均分掩盖。
- 运行记录含任务集版本、数据集指纹、模型名、模式、开始/结束时间及逐题结果；不含密钥。
- 后端评测测试和前端构建通过；交付结构图与流程图。

## 后续改进候选

- 扩充人工校验题库与隐藏 test split；加入指标口径、时间边界和复杂 JOIN 的变异数据。
- 重复运行、Pass³ 与结果一致性；模型/Prompt/检索配置对比。
- 模型每一步决策、Token 与阶段耗时的细粒度追踪。
- 对解释和澄清质量加入经人工校准的可选 LLM grader。
- 外部工具面扩大后再引入容器隔离和更细粒度资源预算。

## 决策来源

- 用户确认：现有 Vue 管理员页面；允许 UI 手动发起受限的远程评测。
- OpenJudge：grader、runner 与结果聚合思路，见 https://github.com/agentscope-ai/OpenJudge 。
- Claw-Eval：任务、fixture、轨迹、分维度和重复试验思路，见 https://github.com/claw-eval/claw-eval 。

## 待验证

实现中需确认现有服务的持久化副作用能否在评测模式下隔离；若不能，首版实时评测须使用专用 session 命名空间并避免写入用户记忆。任务 oracle 需要在固定 fixture 上独立校验。
