## 1. 客户等级订单数与实付销售额

- 题目 ID：`join.customer_orders`；审核指纹：`373d33774e987fa5`。
- 题面：按客户等级统计2026年8月已支付订单的订单数和实付销售额。
- 标准口径：`orders_current.customer_id = customers.customer_id`；过滤 8 月和已支付；每等级 `COUNT(DISTINCT order_id)` 与 `SUM(paid_amount)`。基础客户表 `customer_id` 唯一，基础当前订单 `order_id` 唯一。

| 数据 | 普通客户：订单数 / 销售额 | 重点客户：订单数 / 销售额 | 战略客户：订单数 / 销售额 |
| --- | ---: | ---: | ---: |
| base | 106 / 5,474,717.37 | 48 / 3,769,570.55 | 54 / 6,414,338.77 |
| edge_v1 | 108 / 5,475,082.37 | 48 / 3,769,570.55 | 56 / 6,415,438.77 |
| edge_v2 | 108 / 5,475,082.37 | 48 / 3,769,570.55 | 57 / 6,416,138.77 |

错误样例 `customer_orders.join_on_region` 在三套数据上均与标准结果不同。人工请确认“订单数”按订单去重以及客户等级归属符合预期。

## 2. 地区去重客户数

- 题目 ID：`grain.unique_customers`；审核指纹：`9fe9173d05ba0db6`。
- 题面：按地区统计2026年8月已支付订单的去重客户数。
- 标准口径：过滤 8 月和已支付；每地区 `COUNT(DISTINCT customer_id)`。

| 数据 | 华东 | 华南 | 华北 | 西南 |
| --- | ---: | ---: | ---: | ---: |
| base | 8 | 8 | 7 | 7 |
| edge_v1 | 8 | 8 | 7 | 7 |
| edge_v2 | 8 | 8 | 7 | 7 |

三套结果相同表示增补订单没有增加该口径下的独立客户。错误样例 `unique_customers.count_rows` 在三套数据上均与标准结果不同。人工请确认跨地区的同一客户是否应在各地区分别计一次；当前答案按“地区内去重”处理。

## 3. 七月历史与八月当前销售额

- 题目 ID：`time.july_august`；审核指纹：`a6203ede45bb6aaa`。
- 题面：分别统计2026年7月历史订单和8月当前订单的已支付实付销售额，按月份输出。
- 标准口径：7 月只读 `orders_history`，8 月只读 `orders_current`；分别过滤月份与已支付状态；返回两行。

| 数据 | 2026-07 | 2026-08 |
| --- | ---: | ---: |
| base | 16,145,060.58 | 15,658,626.69 |
| edge_v1 | 16,146,310.58 | 15,660,091.69 |
| edge_v2 | 16,146,310.58 | 15,660,791.69 |

错误样例 `july_august.current_only` 在三套数据上均与标准结果不同。人工请确认历史与当前表的月份归属以及只统计已支付订单符合业务语义。

## 4. 已修正的目标对比题面

`mock.target_comparison` 原题只写“销售目标”，但基础数据同时包含 2026 年 7 月与 8 月目标，标准 SQL 固定选 8 月。任务集 v5.1 把题面明确为“对比2026年8月各地区已支付订单的实付销售额和当月销售目标”，标准 SQL 与数据未改。修订后的审核指纹为 `3847ddbc4d30c2ee`，需要管理员重新核验。基础数据的“地区＋月份”目标键唯一。错误样例 `target.omit_month` 在三套数据上被识别；`target.omit_paid_status` 在 `edge_v1` 和 `edge_v2` 被识别，在 `base` 中未被识别。
