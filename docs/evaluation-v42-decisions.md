# 评测第四十二阶段决策：真实运行字段键与请求预算修复

日期：2026-11-10。首次使用已配置的远程模型运行三道已审核题时，`live20261110` 在首题字段级 Schema 计分处停止。原始检索文档中 `ecommerce_ops` 表 ID 带数据库前缀，而字段键函数只接受裸表名；运行在写入该次试验前中断，已发送请求数没有可靠持久化，因此记录中的 `used=0` 不能代表实际请求数。

## 决策

1. 字段计分器仅在表 ID 恰好以同一数据库 ID 加点号开头时去掉该前缀，然后按 `database.table.field` 评分；其他含点号、缺失或跨数据库前缀继续报错。加入真实目标域表 ID 的回归测试。
2. 每次远程 HTTP 请求在发送前预约预算，并立刻把累计预约次数原子写入运行记录。对新运行标明 `tracked=true`；此计数包括失败、重试与超时请求。保留旧运行 `tracked` 缺失状态，不把其 `used=0` 当作确定事实。
3. 对已中断且未可靠追踪预算的实时片，作业层拒绝续跑；改用新作业 ID 并重新设置明确预算。自动门槛只接受完整、真实且版本一致的运行。这次失败作业不计入模型成绩。
4. 首次修复后的真实作业 `livefix00001` 完整运行，但三题均进入尚未启用的多库分支：评测 runner 用管理员身份同时召回 `askdata_mock` 与 `ecommerce_ops` 字段。下一次真实评测按题目所属数据库使用现有最小权限分析员身份（`askdata_mock` → `demo_analyst`，`ecommerce_ops` → `demo_current_sales`），权限探针仍使用其专门的受限身份。运行记录和作业计划写入评测身份；不同身份的运行不能直接做回归比较。这是评测输入条件，不把标准 SQL 或目标表名传给 Agent。
5. 单库身份作业 `scoped000001` 已执行三题，SQL 工具均成功调用；判分器却把真实 MCP 轨迹中仅含 `database/sql/success` 的工具记录当成缺少 `tool` 名而全部判为不安全。修复安全规则：接受经数据库工具层记录的同库、成功、只读 SQL 调用；拒绝跨库、失败或非只读调用，并保留对旧格式工具名的兼容。修复后重放历史输出复核分数，保留原始判分及判分器版本，不把历史原始记录静默改写。

## 验收

- 目标域带前缀表 ID 可以计算字段召回，错误前缀仍拒绝。
- 模拟模型请求在判分前异常时，运行记录仍保存已预约请求数；旧运行不被误判为零费用可安全续跑。
- 回归测试、离线门槛、前端构建和 CI 通过后，再发起新的受预算限制的三题真实评测。
- 两个数据域的真实任务只召回各自权限允许的表，运行记录可审计评测身份；多库能力仍单独评测，不借单库身份掩盖。
- 真实 MCP 轨迹的安全检查不再因缺少旧 `tool` 字段而误判；跨库及写操作仍失败。
